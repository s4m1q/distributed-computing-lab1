# Распределённые вычисления · Лабораторная работа № 1

Командная работа по параллельному программированию на **C и POSIX Threads**.
Реализованы поиск точек множества Мандельброта, моделирование гравитационного
взаимодействия N тел и собственная блокировка чтения-записи.

[Журнал измерений](report/results_2026-10-17_22-08-42.txt)

## Быстрый старт

Поддерживаемая среда — **Ubuntu 24.04 LTS**, в том числе в **WSL2** на Windows 11.
В WSL удобно хранить рабочую копию в домашнем каталоге Linux.

```bash
git clone https://github.com/s4m1q/distributed-computing-lab1.git
cd distributed-computing-lab1
bash install_dependencies.sh
make
make check
```

Репозиторий закрытый: для клонирования требуется авторизация GitHub и доступ к нему.
Если файлы скачаны архивом, начните с перехода в распакованный каталог проекта.

Установщик ставит GCC, Make, Python, Matplotlib, Git и утилиты для замеров через
репозитории Ubuntu. Для установки используется `sudo`. Установка зависимостей,
сборка и запуск программ выполняются отдельными командами.

Проверить готовность окружения без установки пакетов:

```bash
bash install_dependencies.sh --check
```

`make check` проверяет синтаксис Bash и Python, собирает программы и запускает
имеющийся тест собственной блокировки на 4 и 18 потоках.

## Запуск задач

Команды ниже выполняются из корня репозитория после `make`.
Выходные файлы примеров сохраняются в игнорируемый Git каталог `results/`.

### 1 Множество Мандельброта

```bash
mkdir -p results
./lab1_pthreads/task1_mandelbrot/mandelbrot 4 100000 results/mandelbrot.csv
python3 lab1_pthreads/task1_mandelbrot/plot_mandelbrot.py \
  results/mandelbrot.csv results/mandelbrot.png
```

Первый аргумент задаёт число потоков, второй — число принимаемых точек.
Каждый поток заполняет свой участок результата и использует отдельное состояние
генератора. Точка принимается, если за 1000 итераций не обнаружен выход за радиус 2.
CSV имеет заголовок `x,y`.

### 2 Задача N тел

```bash
mkdir -p results
./lab1_pthreads/task2_nbody/nbody 4 31536000 \
  lab1_pthreads/task2_nbody/solar.txt 3600 24 results/nbody.csv
python3 lab1_pthreads/task2_nbody/plot_nbody.py results/nbody.csv results/nbody.png
```

```text
./nbody nthreads tend input.txt dt [out_every] [output.csv]
```

Вход: число тел, затем строки `mass x y z vx vy vz` в единицах СИ.
Выход: `t,x1,y1,...,xn,yn`. Расчёт трёхмерный, в файл выводится проекция `xy`.
Параметр `out_every=0` отключает CSV для измерений производительности.

Основная версия `nbody` использует третий закон Ньютона, локальные массивы сил
и два барьера на шаг. Сравнительная `nbody_basic` собирается из того же файла
с `-DBASIC` и рассчитывает оба направления каждой пары. В обеих версиях
применяется явный метод Эйлера первого порядка.

### 3 Блокировка чтения-записи

```bash
./lab1_pthreads/task3_rwlock/test_rwlock 4 20000

# 1000 начальных ключей; 100000 операций; 80% поиска и 10% вставок
printf '1000\n100000\n0.8\n0.1\n' | ./lab1_pthreads/task3_rwlock/ll_my 4
printf '1000\n100000\n0.8\n0.1\n' | ./lab1_pthreads/task3_rwlock/ll_lib 4
```

`ll_my` использует `my_rwlock_t`, `ll_lib` — библиотечную `pthread_rwlock_t`.
Код списка у них общий. Собственная блокировка построена на мьютексе и двух
условных переменных с приоритетом ожидающих писателей.

## Измерения производительности

```bash
RUNS=5 bash run_benchmarks.sh
```

Скрипт собирает задачи, выполняет все нагрузки и сохраняет журнал
`results_<дата>_<время>.txt` в корне проекта. Для каждого сочетания нагрузки,
версии и числа потоков записываются минимум и среднее из `RUNS` повторов.
Список потоков зависит от `nproc`; на ноутбуке команды это 1, 2, 4, 8, 16, 18 и 36.

| Нагрузка | Параметры |
| --- | --- |
| Мандельброт | 500000 принятых точек |
| N тел, обе версии | 2000 тел, 100 шагов, CSV отключён |
| Список с преобладанием поиска | 1000000 операций, 99,9% поиска |
| Список со смешанной нагрузкой | 100000 операций, 80% поиска |

Запустить отдельный замер можно из каталога задачи:

```bash
cd lab1_pthreads/task1_mandelbrot
THREADS="1 2 4 8" bash bench.sh 500000 5
```

Для расчёта ускорения в задачах Мандельброта и N тел первым значением `THREADS`
должен быть `1`. Новые журналы и сгенерированные данные игнорируются Git;
журнал, использованный для итогового отчёта, сохранён отдельно в `report/`.

## Результаты команды

Последний эксперимент: **17 октября 2026 года**, Intel Core Ultra 5 125H,
32 ГБ ОЗУ, Ubuntu 24.04.5 LTS в WSL2, GCC 13.3.0.
Измерены 49 конфигураций, по пять повторов каждой.

| Задача | Лучшее минимальное время | Ускорение относительно той же версии на 1 потоке |
| --- | --- | --- |
| Мандельброт | 0,111132 с, 36 потоков | 9,62 |
| N тел с третьим законом Ньютона | 0,112290 с, 18 потоков | 4,41 |
| Список, 99,9% поиска, библиотечная блокировка | 0,284290 с, 4 потока | 2,49 |
| Список, 99,9% поиска, собственная блокировка | 0,385684 с, 4 потока | 1,83 |

На 36 потоках минимальное время Мандельброта на 0,66% меньше, чем на 16.
При 80% поиска обе реализации списка показали лучшее время на одном потоке.
Подробная методика, средние времена и ограничения приведены в
[отчёте](report/lab1-report.pdf).
